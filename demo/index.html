Growth asks whether a change deserves attention in a growth story. Value emphasizes valuation context. Stability gives a downward price move higher relevance.

Relevance is not the same as the final attention tier. Magnitude and data confidence also contribute. None of these is a buy/sell verdict.

Important distinction. Objective score ≠ event attention. The objective metrics determine how the company is evaluated, while objective relevance also influences which changes/events deserve attention. These are related but different calculations.

06 / Why we built it this way

Reduce noise. Preserve context. Stay simple.

The interesting work is deciding what to remember, what to surface, and where complexity earns its place.

01 / Persistence

Why PostgreSQL?

Watchlists, market history and acknowledgement boundaries belong in a durable, relational store shared across sessions and devices.

02 / Structure

Why a modular monolith?

Keep ingestion, detection, intelligence and persistence clearly separated without turning each boundary into a network dependency.

03 / Independence

Why a provider contract?

Business logic consumes validated observations. Historical collection and runtime replay stay separate from scoring and user-facing explanations.

Latency & simplicity

Where did we save unnecessary work?

No invented benchmarks
01

One ingestion stream, many watchlists

Market observations are stored once and shared by user reads. Each user does not launch another market-data download.

02

Cache and synchronize the right reads

React Query keys cache watchlist, stock and objective-specific data. Pages poll every five seconds; acknowledgement updates the list cache without broadly invalidating every query.

03

Bound history and keep calls local

Charts read at most 180 indexed history points. In-process service calls avoid unnecessary distributed hops. This describes design choices, not measured latency gains.

PostgreSQL · canonical state

Current: one API service and a replay worker with PostgreSQL. Stateless request authentication makes more API instances possible; this is not a deployed cluster.

Later, if justified: Redis, WebSockets, dedicated ingestion services, event pagination and coordinated workers. The existing replay cursor is not persisted across restarts.

Security & honest boundaries

Your watchlist belongs to you.

  • JWT-authenticated API requests
  • bcrypt password hashing
  • Watchlist ownership and stock membership checks
  • Validated request/observation schemas
  • Server-side persistence
  • Environment-configured JWT secret

The local Compose setup has a development secret placeholder. The project ignores local .env files. Neither this tour nor these facts imply a security audit or production hardening.

Keep the distinction clear. This HTML has no login, database, private account, or real authentication. It explains those controls in the actual app.

08 / Decisions you can defend

Every shortcut has a boundary.

Engineering judgment means explaining both the benefit and what you give up.

The problem

A snapshot loses the story.

Traditional watchlists show where prices are. Returning users have to remember what they saw before.

Our approach

Remember the boundary.

Persist what the user acknowledged and explain material events newer than that point.

Our principle

Complexity should earn its place.

A useful explanation, trustworthy state and repeatable behavior matter more than extra infrastructure.
